# 模型接入与运营第一版

## 目标和范围

让管理员在一个流程中接入模型、验证并上线，同时独立控制用户是否看见模型和是否可以调用。复用现有渠道、模型价格、路由和结算体系；第一版不做定时探测、自动同步官方价格或改变故障转移策略。

## 接入流程

1. 管理员选择已有渠道，或填写新渠道名称、HTTPS 地址和密钥。密钥只由服务端保存，不返回前端。
2. 服务端经现有安全上游请求机制尝试读取模型列表，允许多选；接口不可用时可手动输入上游模型名。对外名称默认与上游名称相同，可编辑，冲突时提示用户选择现有模型或改名。
3. 每个模型填写输入、输出及缓存成本和售价、上下文及输出上限；支持按倍率填充，但展示和保存明确的最终数值。统一展示单位为人民币每百万 token，转换到现有微元每千 token 时检查精度和范围。成本缺失显示为未知，不能视为零；预计毛利按对应 token 类型单独计算，成本未知或售价为零时显示不可计算。展示渠道执行倍率后的实际售价；缓存价格为零的实际回退规则要与计费一致。
4. 对选中的每个模型分别进行最小真实推理测试，显示时间、成功或失败及可读错误；测试可能产生上游费用。测试单个模型不改变其他模型状态，不以模型列表接口成功代替推理成功。测试失败允许保存为草稿，不能标为已验证。
5. 最终确认前展示模型、渠道、实际售价及测试结果；选择保存草稿或上线。草稿默认不展示、不允许调用。上线需要完整且有效的价格和映射；未通过测试时明确提示并要求管理员主动确认。保存应避免部分失败后留下用户可见的半成品，并记录管理员审计。

草稿独立于现有模型、价格和渠道记录保存。为已有在线模型添加渠道时，草稿不能修改该模型的价格、展示或调用状态，也不能提前加入线上映射；界面展示现有价格，修改价格作为单独明确确认的变更。发布时在事务内校验模型和渠道版本并合并新增映射；检测到其他管理员并发变更时停止发布、保留草稿并提示重新加载比较，不能覆盖已有配置。事务失败时线上数据保持原状。渠道地址、密钥、上游模型名或映射变更后，对应测试结果立即失效，发布前须重新测试或按未通过测试的流程明确确认。

## 状态和目录

现有模型价格的 enabled 继续控制是否允许调用；新增独立的公开展示属性。旧记录缺失展示属性时视为展示，确保迁移前行为一致。隐藏只影响首页、模型广场、公开模型详情及用户模型选择器和模型发现接口，不影响已知模型 ID 的直接调用、渠道配置或价格。停用调用时即便设置展示也不对普通用户展示。管理员始终能查看和编辑隐藏及停用的模型。原有 API 权限约束继续生效。

健康信息与展示及调用开关分离。第一版记录每个渠道和模型最近一次手动测试时间、结果及错误分类（鉴权、余额不足、限流、上游异常、超时、其他），并标明未测试；测试结果不自动修改展示或启用状态，不替代现有渠道冷却策略。错误展示不得包含密钥或完整响应中的敏感信息。后台模型表提供展示、调用、最近测试结果和测试入口。

## 兼容与验证

保留现有 API 请求格式、模型 ID、计费及渠道优先级；不自动修改已有模型状态。历史使用记录与审计记录不受渠道或模型配置调整影响。增加测试覆盖旧数据默认展示、隐藏模型无法被发现但仍可直接调用、停用模型不可调用、渠道与模型映射校验、逐模型测试的成功和错误分类、价格单位转换与实际计费预览一致，以及草稿和失败保存的隔离。验证上游不支持模型列表时的手动接入和多模型部分测试失败；验证管理员界面核心流程与移动端可操作性。
